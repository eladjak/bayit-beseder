# Local visual evidence

Viewport captures are 375 × 812 at device scale 1, Hebrew locale, Jerusalem time. `before` is Git revision `8c90c57`; `current` is `71c48a4`; `new` is the implementation working-tree snapshot identified by the manifest below. Images are real local Next.js renders, but the user, session, household, task data, categories, completions and other database responses are synthetic. The local mock runs on 127.0.0.1:54329, does not persist anything and never connects to a live database. Browser requests outside loopback are blocked. The mock cannot validate real authentication, RLS, database persistence, network failures or production assets. Date-sensitive content reflects the capture date.

To make the three screens comparable, local storage marks onboarding, welcome gift and first-visit tips dismissed, and seeds unlocked pet/background collections. Screenshots suppress only the Next.js development indicator (`nextjs-portal`). They show the actual UI and fixture-driven state, not production data. The task completion click asserts a success toast and completed state in the mock; the old revision leaves its open row stale until refresh. The mock implements both the older direct completion write and the newer completion RPC. The dashboard-empty and tasks-empty cases use a separately reset empty task fixture; dark uses the app's own theme setting.

Reproduce with Node 22, Python/Pillow, Playwright and FFmpeg installed. Start `scripts/joy-mock.cjs`; start each isolated worktree with `NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:54329 NEXT_PUBLIC_SUPABASE_ANON_KEY=local-mock node node_modules/next/dist/bin/next dev --webpack -p PORT -H 127.0.0.1`; then reset with `curl http://127.0.0.1:54329/reset` and run `NODE_PATH=/tmp/joy-browser/node_modules /opt/node22/bin/node scripts/joy-capture.cjs PORT LABEL`. Sequential captures are necessary because the mock has one in-memory state. Generate two- or three-column images with `python3 scripts/joy-compare.py before current [new]`. Browser and temporary dependencies are local and uncommitted. A full browser recording is created per run; the short WebM is extracted with ffmpeg and inspected as frames.

The existing Playwright suite runs via `NODE_PATH=/tmp/joy-browser/node_modules /opt/node22/bin/node /tmp/joy-browser/node_modules/@playwright/test/cli.js test --config scripts/joy-e2e.config.cjs`. Its local config points to 3133 and restricts browser DNS to loopback; it does not alter the repository Playwright config. The suite includes conditional and unauthenticated checks, so a passing count does not establish authenticated end-to-end correctness. See `e2e.log` for results and snapshot scope.
