## What I did

### A. Agent-connectability (the priority)
Added a documented, auth-gated **second front door** at `/api/agent/*` so an
external agent (Kami / Box / any Claude / OpenClaw) can command the app — the
named use-case: *"generate a weekly plan and send it to my WhatsApp."*

New endpoints:
- `GET  /api/agent/capabilities` — self-describing manifest (actions, params, auth).
- `POST /api/agent/plan` — generates a balanced weekly plan; returns JSON
  (`PlanSummary`) **+ a ready-to-send Hebrew `whatsappText` block**. Optional
  `householdId` folds in existing tasks + resolves member names. Pure function,
  **no DB writes**.
- `GET  /api/agent/brief` — today's open tasks + overdue + streak, JSON + WhatsApp text.

New code:
- `src/lib/agent/auth.ts` — `verifyAgentRequest()`: Bearer `BAYIT_AGENT_KEY`
  (alias `AGENT_API_TOKEN`), env-only, **fail-closed (503 if unset)**,
  constant-time compare. Separate from `CRON_SECRET`.
- `src/lib/agent/plan-format.ts` — `buildPlanSummary()` + `buildPlanWhatsAppText()`.
- Routes under `src/app/api/agent/{capabilities,plan,brief}/route.ts`.
- Reuses existing patterns: Zod validation, the shared Upstash rate-limiter,
  `generateWeekPlan()`, service-role Supabase, `buildMorningBrief()`.

Docs:
- `docs/AGENT-API.md` — endpoints, params, curl examples, and the explicit
  "agent → generate plan → POST to WhatsApp" flow (shape only; **no real send wired**).
- `.env.example` — added `BAYIT_AGENT_KEY` with generation instructions.
